# Item & Block Source Audit — ClaudeRPG v1.39.0

> Scope: source-level reconciliation of every custom item/block definition in the supplied `ClaudeRPG_Prog_v1_39_0.mcaddon` archive against recipe JSON and relevant behavior scripts. This is not an in-game or multiplayer test.

## Summary

- **40/40 item definitions** inventoried and mapped to a recipe, scripted creation/drop path, or explicit grant path.
- **4/4 block definitions** inventoried and mapped to recipes and interaction/protection behavior.
- **35/35 recipe JSON files** had already been reconciled against the bilingual `Items.md` tables and definition references; this pass also maps the item families to their use/acquisition scripts.
- No unresolved `crpg:` recipe ingredient or output references were found in the earlier structural reconciliation.
- Runtime outcomes, UI rendering, multiplayer attribution, and client-specific behavior remain unverified without live tests.

## Findings / corrections

- **Gem Fusion wording:** the implementation has two modes. Standard Fusion consumes 5 same-tier Gems; Core Fusion consumes 2 same-tier Gems plus 1 Augment Core. Each produces 1 Gem of the next tier. Both require a Reforge Hammer and durability (base cost 40, reduced by the carried Eternal Hammer passive with integer rounding).
- **Rune grades:** the seven definition files are item shells; their embedded random Rune and tier are written by the Rune item script. They are not normal recipe outputs.
- **Physical Knowledge Book vs menu:** the Script Tool opens the guide menu; the separate “Get Stats Book” action grants the Stats Book. Do not imply that opening the guide menu grants a Knowledge Book item.
- **Drop attribution:** scripted evolved-mob drops are created only for detected player kills; do not describe them as guaranteed drops from environmental/non-player kills.
- **Waypoint permissions:** named Waypoint Stones use owner/Admin checks for break/pickup; Blank Waypoint Stone does not have this protection.
- **Ultimate Picker:** the blacklist is explicit/configured rather than a blanket Creative-only rule for every block; named Waypoint permission checks are separate.
- **Live tests still required:** Sculk Potion refusal/success in-game, item GUI interactions, block protection in multiplayer, item use with inventory edge cases, and all narrow-screen visual checks remain untested. No add-on gameplay code was changed.
